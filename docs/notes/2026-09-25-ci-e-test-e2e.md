# CI sulle pull request e test end-to-end

## Cosa è stato fatto

- `.github/workflows/ci.yml`: a ogni pull request (e a ogni push su `main`) due job. Il primo esegue typecheck e lint. Il secondo avvia uno stack Supabase locale nel runner (migrazioni da zero e seed), scrive `.env.local` con le chiavi locali, poi esegue test del database (RLS), unit test, build e test end-to-end. Nessun segreto nel repository né in GitHub.
- Test end-to-end con Playwright (`e2e/main-flow.spec.ts`, `pnpm test:e2e`): registrazione dal modulo, conferma dell'email letta da Mailpit, due feedback incollati, prima analisi, tema e citazione visibili.
- Modello finto per l'e2e: `e2e/fake-gateway.mts` è un finto Vercel AI Gateway che risponde con un tema costruito dai feedback ricevuti. L'app lo usa perché `AI_GATEWAY_BASE_URL` punta lì (`src/lib/analysis.ts` passa la variabile a `createGateway`; se è vuota vale il Gateway vero).
- `.env.example` con tutte le variabili, e `!.env.example` in `.gitignore`. Le righe non commentate sono quelle obbligatorie in produzione: la skill controllo-rilascio le confronta con Vercel.
- README: sezioni "Avvio" e "Test e pull request".

## Decisioni

- **Finto gateway HTTP invece di un modello finto nel codice.** L'app gira come in produzione, cambia solo l'indirizzo del Gateway: nessun ramo "se test" nel codice dell'analisi.
- **Un solo job per tutti i test che usano il database.** Avviare Supabase costa un paio di minuti: farlo una volta sola tiene la CI più veloce.
- **L'e2e avvia sempre un'app nuova sulla porta 3000** (`reuseExistingServer: false`): un `pnpm dev` già acceso chiamerebbe il Gateway vero. La porta è la 3000 perché il link dell'email di conferma usa `site_url` di `supabase/config.toml`.
- `@playwright/test` aggiunto come dipendenza di sviluppo: serve solo ai test.

## Verifica

In locale: typecheck e lint senza errori, 137 unit test, 53 test RLS, build riuscita, e2e passato sia con `pnpm dev` sia in modalità CI (`CI=1`, build e `pnpm start`). Nel registro `analysis_runs` l'analisi dell'e2e risulta con i token del finto gateway (1200 in ingresso).
